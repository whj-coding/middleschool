# 学习结果真实性与审核操作补全设计

## 目标

在不扩展 MVP 范围的前提下，修复练习结果在前端状态机中被固定答案和固定错因覆盖的问题，补齐后台“需修改/驳回”操作，并移除学情报告中的硬编码百分比。

## 范围

本次只处理三个小切片：

1. 学生提交答案后，前端消费后端返回的结构化判题结果。
2. 内容审核支持“需修改”和“驳回”，并要求填写原因。
3. 学情报告的完成度来自报告 API；无数据时展示中性完成状态，不展示虚构数字。

不处理认证、模块选择与模块诊断、图形坐标范围、向量检索、知识图谱、Obsidian 同步、Prompt 自动优化或其他页面重构。

## 练习结果数据流

`PracticePage` 继续向现有练习提交 API 发送学生真实答案。提交成功后，页面把 API 返回的结果传给 `App`，再由 reducer 更新学习状态。

结构化结果至少包含：

- `correct`：是否正确。
- `answer`：本次真实答案或服务端规范化答案。
- `mistake`：仅错误时存在，包含题目 ID、错因和证据。

正确结果进入学情报告；错误结果进入错题复盘，并只保存服务端返回的错因。API 不可用时保留原型可继续操作的降级能力，但降级结果不得声称已完成判题，也不得生成固定错因。

后端仍是判题与错因结果的事实来源，reducer 不做数学字符串判定。

## 审核操作

沿用现有内容审核 API 和服务层结构，增加：

- “需修改”：内容可再次编辑和提交审核。
- “驳回”：内容不可发布，除非重新进入审核流程。

两个操作都必须携带非空原因。服务端验证状态迁移，并返回更新后的内容状态。前端 API 客户端和当前审核页面只增加对应操作，不重构内容管理界面。

## 学情报告

报告 API 增加可选的完成度字段。学生端有完成度时展示真实百分比；没有该字段时展示“本次已完成”或当前任务状态，不使用本地固定数字。

## 错误处理

- 练习提交失败：保留学生输入，显示可重试状态；不生成错因。
- 审核操作失败：保持原状态并展示失败信息。
- 审核原因为空：前后端都阻止提交。
- 报告完成度缺失：使用中性文本降级。

## 测试与验收

采用测试优先实现，覆盖：

1. 正确答案进入报告且不产生错因。
2. 错误答案进入复盘并保存服务端返回的真实错因。
3. 提交失败不会生成固定错因。
4. “需修改/驳回”需要原因，成功后返回对应状态。
5. 报告展示 API 完成度；字段缺失时不出现 `42%`。

完成后运行相关单测、三个应用的现有测试/构建命令，以及仓库规定的 lint；独立验证和代码审查不得由实现者代替。
