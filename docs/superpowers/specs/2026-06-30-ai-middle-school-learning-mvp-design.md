# 初中 AI 学习软件 MVP 产品设计文档

日期：2026-06-30

## 1. 产品定位

本产品面向初三学生，目标是通过 AI Agent 帮助学生高效备战中考，系统掌握初中数学、物理、化学中的基本概念、公式和原理。

长期产品会覆盖数学、物理、化学三科。MVP 阶段先聚焦数学，并以「一次函数」作为首个完整闭环模块。

产品不是普通题库，而是一个 AI 学习教练。它帮助学生完成：

1. 诊断水平。
2. 联系生活理解概念。
3. 启发式学习。
4. 分层练习。
5. AI 讲解与多轮追问。
6. 错因分析。
7. 再练习。
8. 学情报告。
9. 个性化任务推荐。

## 2. MVP 目标

MVP 的核心目标是验证「一次函数」学习闭环是否有效，而不是追求三科或数学全模块覆盖。

MVP 成功的判断标准：

- 学生知道今天该学什么。
- 学生能理解为什么要学一次函数。
- 学生做错后知道自己错在哪里。
- 学生能获得下一步可执行任务。
- 学生能看到进步，而不是只看到分数。
- 系统能基于诊断、练习和错因生成个性化学习路径。

## 3. 第一版范围

第一版是 Web 应用，学生端优先，预留家长端、老师端、支付和多学科扩展能力。

MVP 首个高质量闭环模块是「一次函数」，覆盖：

- 变量与函数关系。
- 正比例函数、一次函数。
- `y = kx + b` 中 `k` 和 `b` 的意义。
- 图像、斜率、截距、增减性。
- 求解析式。
- 图像读信息。
- 生活应用建模。
- 两个方案比较、交点问题。
- 基础、提升、冲刺三层练习。

暂不重点做：

- 三科完整知识体系。
- 家长端。
- 老师端班级管理。
- 支付/会员。
- 拍照手写识别。
- 复杂几何自动理解。
- 强督学、排行榜、积分商城。

## 4. 用户与场景

核心用户是初三学生。

学生画像分为三类：

- 基础薄弱学生：概念、公式、基本题不稳，需要更多讲解和支持。
- 中等学生：常考题和易错点需要突破，需要错因定位和变式练习。
- 高分冲刺学生：需要综合题、迁移能力和规范表达训练。

第一版采用分层机制，同一个知识点按基础、提升、冲刺三层设计。

## 5. 学生学习流程

学生第一次进入系统：

1. 注册或登录。
2. 设置中考数学目标分数，例如 80、100、110+、满分冲刺。
3. 完成 10-15 道简短诊断题。
4. 系统生成第一阶段学习计划。

进入一次函数模块：

1. 学生选择一次函数模块，或接受 AI 推荐。
2. 系统安排 5-8 道模块小诊断。
3. AI 判断学生在概念、表达式、图像、应用建模、综合迁移上的表现。
4. 系统推荐具体学习任务。
5. 学生选择短练 10 分钟、标准 20 分钟或深度 40 分钟。
6. 学生完成生活化讲解、互动理解、分层练习和错题复盘。
7. 系统生成简短反馈、详细报告和下一步个性化任务。

学生可以自由选择模块和知识点，但系统会标注 AI 推荐优先级，并解释推荐理由。

## 6. AI 教练机制

AI 教练以苏格拉底式引导为主，但不能机械反问或让学生烦躁。

默认概念讲解结构：

1. 生活场景引入。
2. 引导问题。
3. 数学抽象。
4. 中考连接。
5. 即时小练习。

做题和讲解支持三种模式：

- 提示模式：正在做题时优先给方向，不直接给完整答案。
- 讲解模式：做完后分步骤讲清楚思路、公式、易错点。
- 答案模式：给完整规范答案，建议在提交答案后或多次求助后开放。

防依赖机制按学生水平分层：

- 基础薄弱学生：多给提示和讲解，减少挫败感。
- 中等学生：先问思路，再定位错误。
- 高水平学生：更多追问和迁移训练。
- 多次求助时，AI 先要求学生说出当前想法，再继续帮助。

当前题目必须支持多轮追问。AI 在一题内记住题目、学生答案、学生步骤、错因和已经讲过的内容。

## 7. 语音交互

第一版支持文字和语音双通道交互：

- 学生可以语音提问。
- 学生可以语音说解题思路。
- 系统把语音转成文字，进入当前题目或任务上下文。
- AI 回答同时生成文字。
- 学生可以播放 AI 语音讲解。
- 语音记录和文字转写可用于错因分析和复盘。
- 界面预留公式、图像、步骤同步高亮能力，MVP 可以先不完整实现。

数学学习不能只依赖语音。题目、公式、图像和步骤必须保留可视化展示。

## 8. 一次函数内容设计

一次函数生活化场景优先选择初三学生熟悉、不幼稚、容易抽象成函数关系的场景：

- 打车费用。
- 手机套餐。
- 打印费用。
- 水电费用。
- 跑步、骑车、路程时间。
- 学习时长与完成题量。
- 两个方案费用比较。

一次函数理解路径：

1. 找变量：哪些量在变化？
2. 看关系：一个量变了，另一个量怎么变？
3. 判断规律：是不是每增加 1 个单位，另一个量都固定增加或减少？
4. 抽象表达：能不能写成 `y = kx + b`？
5. 回到图像：这个关系在图像上为什么是一条直线？
6. 连接中考：题目通常怎么考？

一次函数练习采用二维标签体系：

难度层级：

- 基础。
- 提升。
- 冲刺。

能力类型：

- 概念理解。
- 表达式求解。
- 图像理解。
- 应用建模。
- 综合迁移。

## 9. 交互图像能力

一次函数 MVP 需要支持交互图像，用于帮助学生理解 `k`、`b` 和直线变化。

第一版能力：

- 拖动 `k`，观察直线变陡、变缓、上升、下降。
- 拖动 `b`，观察直线上下平移。
- 判断某个点是否在直线上。
- 展示两条直线交点，解释两个方案费用相同的含义。

后续增强：

- 题目图像自动读取。
- 学生作图判断。
- 图像题作答批改。

## 10. 题库与 Markdown 标准

第一版题库以成熟题库为主。原始资料主要来自 Word、PDF、扫描件、图片，也支持 Markdown。

项目内需要设计题库导入与转换模块，但第一版不完全自研识别能力，优先接入成熟 OCR、版面分析和视觉模型。

题库导入流程：

1. 上传 Word / PDF / 扫描图片 / Markdown。
2. 清晰度检测、倾斜检测、裁切完整性检测。
3. OCR 提取文字、公式、题号、选项、答案、解析。
4. 版面分析把资料切分成单道题。
5. 图形题保留原始题图，并与题目绑定。
6. 视觉模型识别图形类型和关键元素。
7. 系统生成半结构化 Markdown 草稿。
8. AI 自动补充知识点、题型、难度、错因标签候选。
9. 后台人员审核后发布到学生端。

Markdown 是题库标准中间格式。示例：

```md
# 题目ID: MATH-FUNC-LINEAR-001
学科: 数学
模块: 函数
知识点: 一次函数图像
题型: 选择题
难度: 基础
能力类型: 图像理解
答案: B
解析状态: 已有解析
审核状态: 待审核

## 题干
如图，直线 l 经过点 A(0, 2) 和 B(4, 0)，则该直线的解析式是……

## 题图
![题图](images/MATH-FUNC-LINEAR-001.png)

## 图形识别结果
类型: 坐标系直线图
识别元素:
- 点 A(0, 2)
- 点 B(4, 0)
- 与 y 轴交于 A
- 与 x 轴交于 B
置信度: 0.86

## 选项
A. y = 2x + 4
B. y = -0.5x + 2
C. y = 0.5x + 2
D. y = -2x + 4

## 解析
根据两点式或斜率公式……
```

## 11. 图形题识别策略

第一版必须考虑图形题，尤其一次函数中的坐标系、直线图像、交点、方案比较图。

策略：

- 架构按通用图形识别设计。
- 第一版能力重点服务一次函数图像。
- 识别实现优先接入成熟视觉模型/OCR。
- 后台只做清晰度确认、识别结果审核和必要修正。
- 函数图像、统计图优先；复杂几何后续增强。
- 所有图形识别结果必须经过审核后才能用于正式讲解。

一次函数图像识别优先支持：

- 坐标轴。
- 直线。
- 点。
- 截距。
- 交点。
- 刻度。
- 图中标注。
- 两条直线交点表示两个方案费用相同。

识别结果应结构化保存，例如：

```json
{
  "figure_type": "coordinate_line_graph",
  "elements": {
    "points": ["A(0, 2)", "B(4, 0)"],
    "lines": ["line AB"],
    "intercepts": {
      "x": 4,
      "y": 2
    }
  },
  "confidence": 0.86
}
```

## 12. 审核后台

第一版后台不是完整教务系统，只做内容和题库审核。

使用者：

- 内容负责人。
- 数学老师或教研审核者。

权限保持简单：

- 内容负责人：导入、编辑、发布、下架内容。
- 数学老师：审核题目、答案、解析、标签、图形识别结果。

后台模块：

1. 资料导入：Word、PDF、扫描图片、Markdown。
2. 题目审核：题干、选项、答案、解析、知识点、题型、难度、能力类型。
3. 图形识别审核：确认图是否清晰、识别是否准确。
4. 知识内容管理：一次函数核心知识点、生活化场景、引导问题、例题、小练习。
5. 发布控制：控制内容进入学生端或下架。

题目状态至少包括：

- 待识别。
- 识别失败。
- 待审核。
- 需修改。
- 已发布。
- 不可用。

## 13. 学情分析与错因分类

第一版做基础学习档案，后续升级完整学习画像。

基础学习档案记录：

- 目标分数。
- 学习模块和任务进度。
- 每个知识点的诊断结果。
- 练习正确率。
- 错题记录。
- 学生答案和步骤。
- 语音提问转写内容。
- AI 提示/讲解次数。
- 是否查看完整答案。
- AI 复盘结论。
- 推荐任务完成情况。

学情分析采用「底层详细数据 + 学生端简明展示」。

学生端展示：

- 本次完成情况。
- 进步点。
- 当前最薄弱的 1-3 个点。
- 主要错因。
- 下一步建议任务。

后台和 AI 使用详细数据：

- 知识点掌握度。
- 能力类型表现：概念、表达式、图像、应用、综合。
- 难度层级表现：基础、提升、冲刺。
- 错因分布。
- 最近 7 天/30 天变化。
- 错题再练通过率。
- 提示后是否能独立完成。
- 同类题迁移表现。

第一版错因分类：

1. 概念理解错误。
2. 公式/定理使用错误。
3. 审题与建模错误。
4. 图像理解错误。
5. 计算错误。
6. 步骤规范问题。
7. 知识迁移困难。

## 14. 个性化任务

任务由三类因素共同决定：

- 默认中考复习路径。
- 当前诊断和练习表现。
- 学生目标分数。

任务类型包括：

- 概念补习。
- 生活化讲解。
- 例题拆解。
- 分层练习。
- 错题复练。
- 相似题加练。
- 综合迁移题。
- 阶段复盘。

学生完成任务后，反馈采用三层：

1. 简短反馈：正确率、薄弱点、下一步任务。
2. 展开报告：掌握了什么、错因、题型表现。
3. AI 对话复盘：根据学生水平决定多讲解还是多追问。

## 15. AI Agent 架构

第一版不要把 AI 设计成一个万能聊天机器人，而是拆成多个职责明确的能力模块。

建议 Agent：

1. 学习教练 Agent：学生对话、启发式讲解、多轮追问、错题复盘。
2. 诊断 Agent：判断薄弱点、能力类型和错因。
3. 任务推荐 Agent：生成下一步学习任务。
4. 题库处理 Agent：题目切分、Markdown 结构化、标签候选、解析补全。
5. 图形识别 Agent：调用视觉模型识别函数图像、统计图、简单几何图。
6. 内容审核辅助 Agent：发现题目解析不一致、标签不合理、图形识别低置信度等问题。
7. 报告生成 Agent：把结构化学情数据转成学生能看懂的简明报告。

模型策略采用分层模型策略：

- 题库入库、解析生成、图形识别：可用更强模型，离线处理。
- 实时答疑：响应快、成本可控，复杂问题升级强模型。
- 错因诊断：模型 + 规则共同判断。
- 学情报告：基于结构化数据生成。
- 语音输入：语音转文字模型。
- AI 讲解播放：文字转语音模型。

输出控制：

- 关键学习场景模板化，普通追问自然对话。
- 概念讲解模板：生活场景 -> 引导问题 -> 数学抽象 -> 中考连接 -> 小练习。
- 错题解析模板：学生思路 -> 错因定位 -> 分步提示 -> 正确解法 -> 同类题建议。
- 学情报告模板：本次表现 -> 进步点 -> 薄弱点 -> 主要错因 -> 下一步任务。
- 任务推荐模板：推荐原因 -> 任务内容 -> 预计时间 -> 完成标准。
- 图形识别结果模板：图形类型 -> 关键元素 -> 置信度 -> 待审核字段。

质量控制：

- 关键题目解析必须来源于已审核题库或审核通过的 AI 解析。
- AI 不确定时要标记不确定，不能编造图形条件。
- 低置信度图形识别不能直接用于学生讲解。
- 答案模式建议在学生提交答案后开放。
- AI 讲解和诊断结果要可追踪，方便审核和优化。

## 17. MVP 验收标准

MVP 必须跑通：

1. 学生注册/登录。
2. 设置中考数学目标分数。
3. 完成简短诊断。
4. 进入一次函数模块。
5. 完成模块小诊断。
6. 获得 AI 推荐学习任务。
7. 学习一次函数核心概念和生活化场景。
8. 使用交互图像理解 `k`、`b` 和直线变化。
9. 完成分层练习。
10. 做错后获得 AI 讲解、提示和多轮追问。
11. 支持语音输入和 AI 语音播放。
12. 生成错因分析和简明学情报告。
13. 推荐下一步个性化任务。
14. 错题进入复练。

内容侧标准：

- 一次函数核心知识点完整。
- 覆盖基础、提升、冲刺三层题。
- 题目具备能力类型标签：概念、表达式、图像、应用、综合。
- 核心生活化场景人工配置。
- 题库支持 Markdown 入库。
- PDF/扫描/图片支持半自动转换。
- 图形题保留原图，并有 AI 识别结果和审核流程。
- 所有发布给学生的题目和解析必须审核通过。

AI 侧标准：

- AI 能根据学生表现判断主要错因。
- AI 能按模板讲解概念、错题、学情和任务。
- 当前题目内支持多轮追问。
- 支持提示模式、讲解模式、答案模式。
- 支持语音输入转写和 AI 语音播放。
- 对不确定内容能标记，不编造图形条件。
- 学情报告基于结构化数据生成。

体验侧标准：

- 学生知道今天该学什么。
- 学生能理解为什么要学一次函数。
- 学生做错后知道自己错在哪里。
- 学生能得到下一步可执行任务。
- 学生能看到进步，而不是只看到分数。
- 学习任务可控制在 10/20/40 分钟三种时长。

## 18. 阶段路线

第一阶段：产品需求和学习闭环设计。

第二阶段：原型设计。

第三阶段：技术方案。

第四阶段：MVP 开发。

第五阶段：试用与迭代。

后续每次进入开发前，先确认当前阶段目标，不要直接扩展到全量三科。
