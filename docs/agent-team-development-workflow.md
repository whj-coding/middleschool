# Agent 团队开发组织方案

日期：2026-06-30

## 1. 组织原则

本项目后续按 Agent 团队方式推进。主 Agent 负责统筹目标、拆分任务、整合结果和最终判断；专业 Agent 负责探索、产品、架构、设计、开发、测试、审核等独立工作。

基本原则：

- 先设计，后实现。
- 先小闭环，后扩展。
- 先一次函数 MVP，后数学其他模块，再扩展物理、化学。
- 每个阶段都要有明确交付物。
- 作者和审核分离，不能自己写完自己批准。
- 重要结论必须有文档沉淀。
- 完成前必须验证，不能只凭感觉宣布完成。

## 2. 推荐 Agent 角色

### 2.1 主控 Agent

职责：

- 维护项目目标和阶段边界。
- 读取并更新 `AGENTS.md`、产品设计文档和计划文档。
- 拆分任务，分派给专业 Agent。
- 汇总不同 Agent 的结果。
- 决定是否进入下一阶段。

主控 Agent 不直接承担所有细节工作，除非任务很小。

### 2.2 产品分析 Agent

职责：

- 梳理学生学习流程。
- 明确 MVP 需求和非 MVP 范围。
- 发现需求冲突、遗漏和不清晰之处。
- 维护产品需求文档。

适用阶段：

- 产品需求。
- 学习闭环设计。
- 试用反馈分析。

### 2.3 教研内容 Agent

职责：

- 设计一次函数知识结构。
- 设计生活化引入、引导问题、例题和即时练习。
- 定义题目标签：知识点、难度、题型、能力类型、错因类型。
- 审查 AI 讲解是否符合初三中考数学表达。

适用阶段：

- 一次函数内容建设。
- 题库入库审核。
- 错因分类优化。

### 2.4 UX / 原型设计 Agent

职责：

- 设计学生端页面流程。
- 设计学习任务页、练习页、AI 复盘页、学情报告页。
- 设计后台审核流程。
- 确保初三学生使用时清楚、低压力、可持续。

适用阶段：

- 原型设计。
- 交互优化。
- 试用反馈迭代。

### 2.5 技术架构 Agent

职责：

- 设计系统架构。
- 定义前端、后端、数据库、AI 服务、题库导入、语音、图形识别之间的边界。
- 设计数据模型。
- 评估扩展到多学科、家长端、老师端的可行性。

适用阶段：

- 技术方案。
- 数据模型设计。
- 关键技术选型。

### 2.6 AI Agent 架构 Agent

职责：

- 设计学习教练 Agent、诊断 Agent、任务推荐 Agent、题库处理 Agent、图形识别 Agent、报告生成 Agent。
- 定义每个 Agent 的输入、输出、触发时机、失败处理。
- 设计提示模式、讲解模式、答案模式。
- 设计 AI 输出模板和质量控制规则。

适用阶段：

- AI 能力设计。
- 模型调用策略。
- Prompt 和评估规则。

### 2.7 题库与文档处理 Agent

职责：

- 设计 Word/PDF/扫描件/图片/Markdown 入库流程。
- 设计 OCR、版面分析、公式识别、图形识别流程。
- 定义 Markdown 中间格式。
- 定义审核状态和错误处理。

适用阶段：

- 题库导入模块。
- 图形题识别流程。
- 后台审核功能。

### 2.8 前端开发 Agent

职责：

- 实现学生端 Web 界面。
- 实现交互图像组件。
- 实现语音输入、语音播放交互。
- 实现后台审核界面。

适用阶段：

- MVP 开发。
- UI 调整。
- 浏览器验证。

### 2.9 后端开发 Agent

职责：

- 实现账号、学习档案、任务、题库、错题、学情数据接口。
- 实现 AI 调用编排。
- 实现题库导入、审核、发布流程。
- 实现权限和审计记录。

适用阶段：

- MVP 开发。
- 数据接口。
- 后台流程。

### 2.10 测试与验证 Agent

职责：

- 制定测试策略。
- 验证学生学习主流程是否跑通。
- 验证题库入库、图形识别、AI 讲解、语音能力。
- 记录失败点并推动修复。

适用阶段：

- 每个开发阶段结束前。
- MVP 试用前。
- 修复回归问题时。

### 2.11 代码审核 Agent

职责：

- 对实现结果做独立代码审查。
- 重点检查功能遗漏、数据风险、安全问题、测试缺口和可维护性。
- 不能由同一个上下文自写自审。

适用阶段：

- 每个重要功能完成后。
- 合并或发布前。

## 3. 阶段工作流

### 阶段 1：需求与闭环确认

目标：

- 固化产品设计文档。
- 明确一次函数 MVP 边界。
- 明确学生学习闭环和后台审核范围。

参与 Agent：

- 主控 Agent。
- 产品分析 Agent。
- 教研内容 Agent。
- AI Agent 架构 Agent。

交付物：

- 产品设计文档。
- 一次函数内容结构。
- 学习闭环流程图。
- 非 MVP 范围清单。

当前状态：

- 产品设计文档已完成初版：`docs/superpowers/specs/2026-06-30-ai-middle-school-learning-mvp-design.md`。

### 阶段 2：原型设计

目标：

- 画出学生端和后台关键页面。
- 验证学生学习路径是否自然。
- 验证 AI 教练介入点是否合理。

参与 Agent：

- UX / 原型设计 Agent。
- 产品分析 Agent。
- 教研内容 Agent。
- 主控 Agent。

交付物：

- 学生端页面流程。
- 后台审核页面流程。
- 一次函数学习任务页原型。
- 练习与 AI 复盘页原型。
- 学情报告页原型。

### 阶段 3：技术方案

目标：

- 确定技术栈。
- 设计系统架构。
- 设计数据模型。
- 设计 AI Agent 调用链路。
- 设计题库导入和图形识别流程。

参与 Agent：

- 技术架构 Agent。
- AI Agent 架构 Agent。
- 题库与文档处理 Agent。
- 前端开发 Agent。
- 后端开发 Agent。
- 测试与验证 Agent。

交付物：

- 技术架构文档。
- 数据模型文档。
- AI Agent 接口设计。
- 题库 Markdown 标准。
- 图形识别审核流程。
- MVP 开发计划。

### 阶段 4：MVP 开发

目标：

- 实现一次函数完整学习闭环。
- 实现学生端、后台审核、AI 对话、语音、题库基础能力。
- 保证每个主流程可测试。

参与 Agent：

- 前端开发 Agent。
- 后端开发 Agent。
- AI Agent 架构 Agent。
- 题库与文档处理 Agent。
- 测试与验证 Agent。
- 代码审核 Agent。
- 主控 Agent。

交付物：

- 可运行 Web 应用。
- 一次函数内容和题库样例。
- 后台审核流程。
- 测试报告。
- 代码审核记录。

### 阶段 5：试用与迭代

目标：

- 让少量初三学生试用。
- 观察完成率、错题改善、AI 讲解满意度、任务推荐有效性。
- 根据真实反馈迭代。

参与 Agent：

- 产品分析 Agent。
- 教研内容 Agent。
- 测试与验证 Agent。
- UX / 原型设计 Agent。
- 主控 Agent。

交付物：

- 试用反馈报告。
- 问题优先级清单。
- 下一轮迭代计划。

## 4. 默认执行协议

每个较大的开发任务按以下顺序执行：

1. 探索：确认现有文件、设计文档、约束和风险。
2. 计划：拆成可验证的小任务。
3. 实现：由执行 Agent 完成具体代码或文档。
4. 验证：由测试/验证 Agent 检查结果。
5. 审核：由代码审核或内容审核 Agent 独立审查。
6. 修复：根据审核和验证问题迭代。
7. 总结：更新文档和下一步计划。

涉及两个以上独立子任务时，优先并行分派 Agent。

作者和审核必须分离：

- 写产品文档后，需要产品/教研/技术视角复核。
- 写代码后，需要测试和代码审查。
- 题库入库后，需要内容审核。
- AI 解析和图形识别结果必须有审核状态。

## 5. 推荐的下一步

当前最合理的下一步是进入「原型设计阶段」，先由 UX / 原型设计 Agent 和产品分析 Agent 输出学生端、后台端的页面流程。

建议优先设计这些页面：

1. 学生首页 / 今日任务。
2. 目标设置与简短诊断。
3. 一次函数模块页。
4. 学习任务页。
5. 交互图像组件。
6. 练习页。
7. AI 讲解与复盘页。
8. 学情报告页。
9. 后台资料导入页。
10. 后台题目与图形识别审核页。

原型确认后，再进入技术方案和 MVP 开发计划。
